# Fluid Particles — Project Overview

A real-time 3D fluid simulation built in Unity using GPU compute shaders (SPH method).
Particles are simulated entirely on the GPU, then rendered as shaded spheres or billboards.

---

## Scene

### `Assets/Scenes/Fluid Particles.unity`
The only scene in the project. Contains four GameObjects:
- **Simulation** — runs the fluid physics and spawns particles
- **Particle Display** — renders particles and foam visuals
- **Main Camera** — orbiting camera with mouse controls
- **Directional Light** — scene lighting

---

## Simulation

### `Assets/Scripts/Simulation/FluidSim.cs`
The core of the project. Manages the entire fluid simulation loop on the GPU.
Each frame it:
1. Applies gravity and external forces
2. Builds a spatial hash of particle positions
3. Computes density and pressure per particle
4. Applies viscosity forces
5. Updates particle positions
6. Optionally updates foam/spray particles and a 3D density texture

**Depends on:** `Spawner3D`, `FluidSim.compute`, `ComputeHelper`, `SpatialHash`

---

### `Assets/Scripts/Simulation/Spawner3D.cs`
Fills one or more cubic regions with evenly-spaced particles at startup.
Supports multiple spawn regions with configurable density, jitter, and initial velocity.
Provides the initial position and velocity arrays that `FluidSim` uploads to the GPU.

**Depends on:** nothing (standalone utility)

---

### `Assets/Scripts/Simulation/Compute/FluidSim.compute`
The GPU compute shader that does all the heavy math:
- External forces kernel
- Spatial hash construction kernel
- Reorder / copy-back kernels (for cache-friendly memory access)
- Density kernel (SPH density estimation)
- Pressure kernel (pressure + near-pressure forces, foam spawning)
- Viscosity kernel
- Position update kernel
- 3D density texture render kernel
- Foam update and compaction kernels

**Depends on:** `FluidMaths3D.hlsl`, `SpatialHash3D.hlsl`

---

### `Assets/Scripts/Simulation/Compute/FluidMaths3D.hlsl`
HLSL header included by `FluidSim.compute`.
Contains the SPH kernel functions (Spiky Pow2, Spiky Pow3 and their gradients)
used to calculate density and pressure contributions between neighbouring particles.

---

### `Assets/Scripts/Simulation/Compute/SpatialHash3D.hlsl`
HLSL header included by `FluidSim.compute`.
Implements the 3D spatial hashing functions that map a particle's grid cell
to a hash key, used to efficiently find all neighbouring particles within the smoothing radius.

---

## Rendering

### `Assets/Scripts/Rendering/Particles/ParticleDisplay3D.cs`
Reads particle positions and velocities from the GPU buffers and draws them
using `Graphics.DrawMeshInstancedIndirect` — meaning millions of particles
are rendered in a single draw call without any CPU readback.
Supports two display modes: **Shaded 3D sphere** and **Billboard quad**.
Also generates a colour gradient texture to colour particles by velocity.

**Depends on:** `FluidSim` (GPU buffers), `ComputeHelper`, `QuadGenerator`, `SphereGenerator`, `Particle3DSurf.shader`, `ParticleBillboard.shader`

---

### `Assets/Scripts/Rendering/Particles/Particle3DSurf.shader`
Renders each fluid particle as a shaded 3D sphere using per-instance GPU instancing.
Colours particles based on their velocity using a gradient texture.

---

### `Assets/Scripts/Rendering/Particles/ParticleBillboard.shader`
Renders each particle as a camera-facing billboard quad.
Lighter alternative to the full sphere shader.

---

### `Assets/Scripts/Rendering/Foam/FoamRenderTest.cs`
Renders foam, spray, and bubble particles that are generated by `FluidSim`
when particles collide at high velocity. Uses an indirect draw call driven
by a counter buffer that tracks the live foam particle count each frame.

**Depends on:** `FluidSim` (foam buffers), `ComputeHelper`, `FoamCountToArgsCopy.compute`, `BillboardFoam.shader`

---

### `Assets/Scripts/Rendering/Foam/BillboardFoam.shader`
Renders foam/bubble particles as camera-facing billboards.
Separate shader from the fluid particles to allow different visual treatment (size, opacity, etc.).

---

### `Assets/Scripts/Rendering/Foam/FoamCountToArgsCopy.compute`
A tiny compute shader that copies the live foam particle count
from the foam counter buffer into the indirect draw arguments buffer,
so the GPU knows how many foam particles to render without a CPU readback.

---

### `Assets/Scripts/Rendering/MeshHelpers/QuadGenerator.cs`
Generates a simple quad mesh at runtime used by `ParticleDisplay3D` in billboard mode.

---

### `Assets/Scripts/Rendering/MeshHelpers/SphereGenerator.cs`
Generates a low-poly sphere mesh at runtime (configurable resolution)
used by `ParticleDisplay3D` in shaded 3D mode.

---

## Camera

### `Assets/Scripts/Demo/OrbitCam.cs`
Attached to the Main Camera. Provides mouse-driven camera controls:
- **Left mouse drag** — orbit around a pivot point
- **Middle mouse drag** — pan
- **Right mouse drag / scroll wheel** — zoom
- **Double left click** — reset camera to its starting position

---

## Helpers

### `Assets/Scripts/Helpers/ComputeHelper.cs`
A static utility class used throughout the project.
Key responsibilities:
- Creating and releasing `ComputeBuffer` and `RenderTexture` objects
- Dispatching compute shaders with automatic thread group calculation
- Creating indirect draw argument buffers for GPU instancing
- Setting multiple buffers on a compute shader kernel in one call

**Used by:** `FluidSim`, `ParticleDisplay3D`, `FoamRenderTest`, `SpatialHash`

---

### `Assets/Scripts/Helpers/SpatialHash/SpatialHash.cs`
Manages the GPU-side spatial hash data structures (keys, offsets, sorted indices).
Each simulation step it sorts particles by their grid cell hash using `GPUCountSort`,
enabling `FluidSim.compute` to find all neighbours within the smoothing radius in O(1).

**Depends on:** `GPUCountSort`, `SpatialOffsetCalculator`, `ComputeHelper`

---

### `Assets/Scripts/Helpers/SpatialHash/Offsets/SpatialOffsetCalculator.cs`
Runs a compute shader that builds the offset table — for each hash bucket,
it records where that bucket's particles start in the sorted array.

**Depends on:** `SpatialOffsets.compute` (loaded from Resources)

---

### `Assets/Scripts/Helpers/SpatialHash/Offsets/Resources/SpatialOffsets.compute`
Compute shader that calculates the start offset of each hash bucket
in the sorted particle array. Runtime-loaded by `SpatialOffsetCalculator`.

---

### `Assets/Scripts/Helpers/GPU Sort/CountSort/GPUCountSort.cs`
Implements a GPU radix/count sort. Sorts the spatial hash keys each frame
so that particles in the same grid cell are contiguous in memory,
enabling fast neighbour lookups in the simulation kernels.

**Depends on:** `Scan`, `CountSort.compute` (loaded from Resources), `ComputeHelper`

---

### `Assets/Scripts/Helpers/GPU Sort/CountSort/Resources/CountSort.compute`
Compute shader that performs the counting and scattering passes of the GPU sort.
Runtime-loaded by `GPUCountSort`.

---

### `Assets/Scripts/Helpers/GPU Sort/CountSort/Scan/Scan.cs`
Implements a parallel prefix-sum (scan) on the GPU.
Used by `GPUCountSort` to convert the count array into offset positions
needed for the scatter pass of the sort.

**Depends on:** `ScanTest.compute` (loaded from Resources)

---

### `Assets/Scripts/Helpers/GPU Sort/CountSort/Scan/Resources/ScanTest.compute`
Compute shader that performs the parallel prefix-sum.
Runtime-loaded by `Scan`.

---

## Data Flow Summary

```
Spawner3D
   └─► FluidSim  ──► FluidSim.compute (GPU)
            │              uses: FluidMaths3D.hlsl
            │              uses: SpatialHash3D.hlsl
            │
            ├─► SpatialHash ──► GPUCountSort ──► Scan
            │                └─► SpatialOffsetCalculator
            │
            ├─► positionBuffer / velocityBuffer
            │        └─► ParticleDisplay3D ──► Particle3DSurf / ParticleBillboard shader
            │
            └─► foamBuffer / foamCountBuffer
                     └─► FoamRenderTest ──► BillboardFoam shader
                               uses: FoamCountToArgsCopy.compute

OrbitCam  (independent — drives Main Camera transform)
ComputeHelper  (utility — used by almost everything above)
```
